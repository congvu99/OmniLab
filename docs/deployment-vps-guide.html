Deploy OmniLab lên VPS

Site tĩnh Astro chạy trên VPS đang có BookSnap + LingoBrain, dùng chung Caddy. Bắt đầu khi code đã push lên GitHub. Không có DB: toàn bộ nội dung bài học nằm trong git, build thẳng vào image. Làm lần lượt chương 2 → 4, mất khoảng 10–15 phút.

Thông số của bạn

Điền vào đây, các lệnh bên dưới tự cập nhật (tô vàng). Chỉ lưu trong trình duyệt này.

Nhãn trên mỗi khối lệnh WINDOWS máy tính của bạn · SERVER phiên ssh vps, user deploy · FILE nội dung một file. Mỗi khối lệnh: bấm Copy, dán nguyên khối.
Điều kiện trước Đã làm xong chương 1–5 của hướng dẫn VPS BookSnap: ssh vps, Docker, DuckDNS, Caddy dùng chung + mạng web, /srv/apps thuộc user deploy.

3Build & chạy

Server
cd /srv/apps/omnilab
bash deploy/deploy.sh
docker compose ps
docker compose logs --tail 20 app
  • Lần đầu 2–4 phút: tải Node + cài thư viện + sharp xử lý ảnh + build 58 trang. Các lần sau nhanh hơn nhờ cache. Log build có 58 page(s) built và sitemap-index.xml created.
  • Kết thúc bằng deploy ok: <commit>. ps: Up … (healthy).
  • Log app là JSON của Caddy ("msg":"serving initial configuration"). Không thấy lỗi error là được.
  • Build dừng ở FIDELITY VIOLATION: nội dung bài học lệch với content-sources/ → sửa trên Windows (pnpm build báo cùng lỗi), push, chạy lại.

4Gắn tên miền + kiểm tra

Server
cat > /srv/caddy/conf/sites/omnilab.caddy <<'EOF'
. {
	header Strict-Transport-Security "max-age=15552000"
	reverse_proxy omnilab:8080
}
EOF
cd /srv/caddy
docker compose exec caddy caddy validate --config /etc/caddy/Caddyfile
docker compose exec -w /etc/caddy caddy caddy reload
  • Không cần encode: Caddy trong image đã nén gzip/zstd, và tự gắn CSP + cache header.
  • HSTS thêm ở Caddy chung vì Caddy trong image chạy HTTP thuần (auto_https off), không biết người dùng đang dùng HTTPS.
  • validate phải in Valid configuration.
Windows
curl.exe -sI https://./
curl.exe -s -o NUL -w "%{http_code}\n" https://./khong-ton-tai
curl.exe -s -o NUL -w "%{http_code}\n" https://./search-index.json
curl.exe -s -o NUL -w "%{http_code}\n" https://./sitemap-index.xml
curl.exe -s -o NUL -w "%{http_code} -> %{redirect_url}\n" http://./
  • Lệnh 1: 200, có Content-Security-Policy, Strict-Transport-Security, Cache-Control: no-cache.
  • Lệnh 2: 404 thật (không trả trang chủ). Lệnh 3, 4: 200. Lệnh 5: 308 -> https://….
Server
H=https://.
curl -s $H/sitemap-0.xml | grep -o '<loc>[^<]*' | head -2
A=$(curl -s $H/ | grep -o '/_astro/[^"]*\.css' | head -1); curl -sI "$H$A" | grep -i cache-control
sudo ss -tlnp | grep -v 127.0.0.
  • Sitemap phải chứa https://./…, không phải omnilab.example.
  • Asset /_astro/*: public, max-age=31536000, immutable.
  • Cổng mở ra ngoài chỉ 22, 80, 443. Thấy 8080 = có cổng lọt.
  • Mở trang trên trình duyệt, vào 1 bài, đánh dấu đọc/lưu → tải lại trang vẫn còn.
  • Trang Tìm kiếm gõ 1 từ → có kết quả (đọc search-index.json).
  • iPhone Safari: Thêm vào màn hình chính → mở được như app.

5Chuyển từ Nhân Hòa (Vibe Deploy)

Không có dữ liệu server để chuyển. Chỉ tiến độ đọc trong trình duyệt người dùng bị ảnh hưởng, vì nó gắn theo tên miền.

Giữ tên miền cũ (trỏ DNS về VPS)Tên miền mới (DuckDNS)
Tiến độ đọc, bài đã lưuGiữ nguyênMất (site không có xuất/nhập), người dùng bắt đầu lại
Cần làmChương 4 dùng tên miền cũ thay cho .; .env đặt SITE_URL = tên miền cũ; hạ TTL 300 giây trước 1 ngày → đổi bản ghi A sang Không cần gì thêm

Chuyển xong và chạy ổn vài ngày thì xoá app trên Vibe Deploy Nhân Hòa để không phải chạy 2 bản.
